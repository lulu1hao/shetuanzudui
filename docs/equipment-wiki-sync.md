# 装备 Wiki 数据同步

装备数值与应用版本分离。部署本次客户端改动后，现有装备的 Wiki 数值变化不需要重新发版。来源为 [THE FINALS 社区 Wiki](https://www.thefinals.wiki/)，不是游戏服务端数据；游戏平衡调整需要 Wiki 编辑者先更新页面。

## 同步流程

1. `App.vue` 启动同步器，启动时检查一次；运行期间每 30 分钟检查一次；恢复联网时立即重试。窗口重新聚焦、恢复可见时补做过期检查。失败后按 1、2、4、8、16、30 分钟退避。退出应用后不运行，下一次启动补做检查。
2. 每批最多 20 个标题，通过 MediaWiki Action API 查询当前修订 ID。只下载修订变化或没有缓存的页面正文。手动同步、距离正文抓取超过 24 小时会重新读取全部正文。
3. 桌面端通过固定 Wiki 域名的 Rust `fetch_equipment_wiki` 命令访问，避免 WebView 跨域限制。浏览器预览使用 API 支持的 `origin=*`。两种路径均限制请求时间，并处理 HTTP/MediaWiki 错误。
4. 从当前 Infobox 读取伤害、弹丸表达式、副攻击、爆头、射速、弹药、换弹、衰减、环境伤害及技能的冷却、次数、范围、持续、治疗、耐久等字段。解析嵌套模板与链接中的分隔符，禁止从历史补丁表匹配旧值。Wiki 明示 DPS 时原样保留，不把自行推算的 DPS 冒充来源数值。
5. 同次刷新 Damage Profile 与当前正文中的攻击时序（连发间隔、蓄力、转管、三段旋转等），不从历史补丁表抽取时序。删除以前硬编码的击杀时间和旧 `ttk`。38 把武器按各自机制重新计算卡片 DPS、排序、详情与对比档案；原表只作对照，例外是通过当前命中数、稳定射速时序校验后的加特林冷启动实测。见 [武器计算口径](weapon-combat-analysis.md)。中文名称和本地图片保留；在线简介使用 Wiki 原文，同步后的装备隐藏静态战术建议，避免本地文案仍含过时数值。
6. 校验后的每件装备保存标题、修订 ID、来源修改时间、检查时间、正文抓取时间。成功项合并，失败项保留完整旧快照与旧修订 ID，下次继续重试。缓存采用新 schema，不能继承旧代码的假成功时间。解析器升级时保留有效旧数值供离线使用，但即使页面修订号未变化，也会重新抓取正文补齐新解析字段。
7. Vue 响应式快照驱动列表、排序、对比与按 ID 选中的检视器一起更新。页面展示成功检查数、变化项与字段前后值、失败原因。只有全部项目检查成功才推进“最近全量检查成功”；存储失败单独提示。

## 验证

```powershell
npm.cmd run test:equipment
npm.cmd run build
cargo check --manifest-path src-tauri/Cargo.toml --offline
node scripts/probe-equipment-wiki.mjs --verify-sync
```

最后一项需要联网：第一轮运行生产同步核心读取全部已知装备，第二轮检查无变化修订不再下载正文。`scripts/tests/fixtures/equipment-wiki.json` 是 2026-09-26 抓取的 86 个页面数值信息框和击杀表片段（附页面修订号与时间），用于离线回归，不作为在线数据源。

## 范围与限制

- 自动同步当前目录中的 86 件装备；新增装备的发现、中文命名与图片资源不在本次自动更新范围。
- Wiki 原文的数值和实测击杀表可能彼此不同步；保留来源原值和修订信息，不自行“修正”社区数据。
- 计算结果明确标注为当前数值推算。未提供的攻击间隔与前摇显示待测，可填实测值试算；不会用旧版本数值补齐。
- 当前数值直接存储于信息框。若 Wiki 改成新的嵌套数据模板或完全不同的页面结构，会显示解析失败并保留缓存，需要适配解析器，不能保证未来任意结构变更无需更新客户端。
- 纯网页发布需要 Wiki 继续允许跨域访问；桌面版使用原生请求，不依赖该跨域配置。
